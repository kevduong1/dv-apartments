# DV Books

Offline-first bookkeeping for a **Series LLC** property portfolio — a parent LLC
with child "series" LLCs, each holding properties and units. The app runs on a
real Postgres database **in the browser** so it works with no connection and is
built to sync to Supabase when the backend is wired up.

Mobile- and iPad-friendly. No hosted database is needed for development.

## Stack

| Concern        | Choice                                                              |
| -------------- | ------------------------------------------------------------------ |
| Framework      | Next.js 16 (App Router) + React 19                                 |
| UI             | shadcn/ui (`radix-luma` preset), Tailwind v4, Hugeicons            |
| Local database | **PGlite** — Postgres compiled to WASM, persisted to IndexedDB     |
| Reactivity     | `@electric-sql/pglite-react` live queries (UI updates on write)    |
| Schema / types | **Drizzle ORM** — one schema → local SQL now, Supabase later       |
| Sync (planned) | Supabase Postgres via a swappable engine in `lib/sync`             |

## Getting started

```bash
pnpm install
pnpm dev
```

Open http://localhost:3000. On first load the browser compiles Postgres, runs
the migrations, and seeds a demo portfolio — no setup, no database to host.

To reset the local data, clear the site's IndexedDB (DevTools → Application →
IndexedDB → `idb://dv-apartments`) and reload.

## How offline-first works here

- **PGlite** is a full Postgres build running in the browser, with its data
  persisted into **IndexedDB** (`idb://dv-apartments`). So "PGlite *or*
  IndexedDB" is really "PGlite *stored in* IndexedDB."
- Reads use **live queries** — inserting a transaction updates every card and
  table on the page instantly, with the network off.
- Writes go through a small **repository layer** (`db/queries.ts`), the seam
  where sync will hook in.

## Project layout

```
app/            Routes, root layout, PWA manifest, the dashboard page
components/     App shell, dashboard widgets, entity switcher, shadcn/ui
db/
  schema.ts            Drizzle schema — the single source of truth
  migrations/          SQL generated by drizzle-kit (also applied to Supabase)
  migrations.generated.ts  Bundled SQL for the in-browser migrator
  migrate.ts           Applies migrations to PGlite on first load
  seed.ts              Demo Series-LLC portfolio (idempotent)
  client.ts            Boots PGlite + Drizzle (singleton)
  provider.tsx         React provider: live queries + `useDb()` for writes
  queries.ts           Repository layer (all writes) — future sync seam
lib/
  sync/                Swappable SyncEngine (currently local-only, no-op)
  supabase/            Env-gated client stub (not connected yet)
  format.ts            Money/date helpers (money stays decimal, never float)
```

## Data model

A categorized ledger (not double-entry):

- `entities` — the LLCs. Self-referencing `parent_id` models the Series LLC.
- `properties` → `units` — a property's rentable units.
- `categories` — income/expense buckets.
- `transactions` — ledger entries; income vs. expense follows the category.

Every table carries `updated_at`, `deleted_at` (soft delete), and `updated_by`
so a last-write-wins sync can be layered on without a schema change.

## Changing the schema

Edit `db/schema.ts`, then:

```bash
pnpm db:generate   # drizzle-kit generate + bundle SQL for the browser
```

## Roadmap

1. **Sync** — connect Supabase; implement a real engine in `lib/sync`
   (ElectricSQL Postgres↔PGlite, or `updated_at`-cursor pull + outbox push).
2. **Auth** — Supabase Auth for the shared dataset; set `updated_by`.
3. **Domain** — leases, tenants, owners/members; per-property P&L and reports.
4. **PWA** — service worker for offline app-shell caching; real app icons.
5. **Storage** — switch PGlite to OPFS (`opfs-ahp://`) for speed; multi-tab via
   the PGlite worker.
